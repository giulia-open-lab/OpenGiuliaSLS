# Saveable & Monitoring

Documentation for Giulia's **Saveable** system — the mechanism that lets any class
expose its computed variables so they can be **written to output files** (Parquet /
NPZ) and **read live while a simulation runs**.

| Page | What it covers |
|---|---|
| **[Saveable Objects](../source/saveable-objects.rst)** | How a class *becomes* a Saveable (inherit, `super().__init__()`, `expose_variables()`), the runtime registry, and `Saveable.get()`. *(reStructuredText — this is the page wired into the Sphinx build.)* |
| **[The Output Module](./output-module.md)** | A map of `giulia/outputs/`: which file does what, the NPZ vs. Parquet formats, `.gof` archives, and where each artefact lands on disk. |
| **[Saveable Output & Export](./saveable-output.md)** | How Saveable variables become output files: the `generic` vs. per-entity (`ue_kpi` / `cell_kpi` / `ru_kpi` / …) Parquet files, `label` / `expose_variable_labels`, and the `fields` filter. |
| **[Reading Parquet Output](./reading-parquet.md)** | How to *read* those Parquet files back: what Parquet is, the [`OutputReader`](../../giulia/outputs/read_outputs.py) API (count → schema → column → values), the equivalent raw-pandas workflow, and the full set of Parquet features (column/row pruning, partitioning, schema). |
| **[Saveable Catalog](./saveable-catalog.md)** | The auto-generated list of every Saveable variable available per preset. Regenerated by [`scripts/generate_saveable_catalog.py`](../../scripts/generate_saveable_catalog.py). |
| **[Saveable Monitor](./SaveAble_monitor.md)** | Reading one or more KPI values **live** during a run via the `Monitor` class, including the threading model. |
| **[Testing the Saveable registry](./saveable-registry-tests.md)** | How to run `tests/test_saveable_registry.py`, why it exists, what each test pins, and how to extend it. |
| **[Testing the Saveable pipeline](./saveable-pipeline-tests.md)** | The end-to-end suites that run **real simulations**: what they cover, the shared fixture API, the rules they follow, and which subset belongs in CI. |
| **[Saveable Concurrency](./saveable-concurrency.md)** | Where the registry lives: one per execution context, why parallel simulations no longer evict each other, and how a reader thread opts in with `Saveable.share_registry`. |

## Notes

- **`saveable-objects.rst` stays under [`../source/`](../source/)** because it is the
  only page currently wired into the Sphinx `toctree` ([`source/index.rst`](../source/index.rst)).
  The Markdown pages here read well directly on a Git host / in an editor.
- The **catalog is generated**: `scripts/generate_saveable_catalog.py` writes
  `docs/output-saveable/saveable-catalog.md`, preserving the hand-written tutorial above the
  generated marker. If you move this folder, update `OUTPUT_MD` in that script.
